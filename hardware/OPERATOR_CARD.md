## 一、接线

| RP2040 引脚 | 接到相机 | 必需？ |
| --- | --- | --- |
| **GND** | 相机 GND（转接板 GND） | ✅ **必需** |
| **GP28（MULTI_TX）** | **相机 RX** | ✅ **必需**（← 就是这个点还没找到） |
| GP27（MULTI_RST） | 相机 RESET | ⭕ 可选（没有就用"拔电池"代替） |
| GP29（MULTI_RX） | 相机 TX | ⭕ 可选（有就能看到相机输出） |

**电平：3.15V · OPEN_DRAIN**（不要 5V 推挽 · 不要注入电源）

## 二、命令（三步）

### 步骤 1：烧 RP2040 固件
```
正式灌入直接使用:
  <repo>/aux_fix/rp2040/uart_boot.uf2

按住 BOOTSEL 插 USB，出现 RPI-RP2 后把 uart_boot.uf2 拖进去；
板子自动重启。该固件已编译为 OPEN_DRAIN，GP28/29/27 分别是 TX/RX/RESET。
```

### 步骤 2：灌 payload（★ 第 1 次：bypass 版）

**有 RESET 线：**
```bash
python3 flash_aux_fix.py --port COM5
```

**没有 RESET 线（拔电池法）：**
```bash
python3 flash_aux_fix.py --port COM5 --no-reset
# ⇒ 脚本开始发前导码+记录（约 1.5 秒）
# ⇒ 此时你【手动装电池 / 按开机键】给相机上电
```

**看到这样的进度就正常：**
```
[1/4] 连接 COM5 @115200 ... OK
[2/4] 复位相机 ... OK          （或 "跳过 RESET"）
[3/4] 启动前导码 (CARRIER) ... OK
[4/4] 灌入 19 条记录 ...
  [ 1/19] ###### 起始哑写 (END_MARKER)
  [ 2/19] ####### MEM_WRITE 0xFE020000  512B
  ...
  [19/19] ############################## 结束哑写 ⇒ 跳转
★ 灌入完成！
```

**正式固件是主机驱动型：RP2040 上电后不会自行发完整记录，必须保持 USB 连接并运行 `flash_aux_fix.py`。**

**没有 RESET 线且相机在循环重启时，可用循环发送：**
```bash
python3 flash_aux_fix.py --port COM5 --no-reset --retry 10
```

### 步骤 3：看 LED 结果 + 重启
```
① 先看 1 次 1 秒长闪（LED 自检）
② 再看 3 次快闪（payload 已启动）
③ 等 payload 完成 SDHCI → 扫目录 → 读写校验
④ 结果会无限循环播报：2 次长闪标记 + N 次短闪，每 3 秒重复
     N=1 成功 / N=2 没找到 / N=3 MMC失败 / N=4 读失败 / N=5 写失败 / N=6 校验失败
⑤ 记下 N，然后断电重启相机
```

## 三、判定

| 重启后的现象 | 含义 | 下一步 |
| --- | --- | --- |
| **正常开机（能进菜单/有画面）** | ✅ **成功！修好了** | 收工 |
| 仍重启循环（闪屏/黑屏） | ❌ 第 1 次失败 | **试第 2 次：`-u` 版** ↓ |
| 完全没反应（连灯都不亮） | ⚠️ 可能没上电/别的 | 拔电池，检查供电 |

### 第 2 次尝试（用 A7IV 的真实解锁码）
```bash
python3 flash_aux_fix.py --port COM5 \
    --unlock-code 0x2CF25621
# 相机会自动生成 18 条记录；无需手工指定 records_unlock_a7iv.bin
# 如需使用已生成的原始记录流，按 RP2040 BLOB 协议逐条发送 records_unlock_a7iv.bin
```

| 第 2 次结果 | 下一步 |
| --- | --- |
| 正常开机 | ✅ 成功 |
| 仍循环 | ❌ **停手** —— 别磨板。等大佬的引脚答案或送修 |

## 四、探测阶段（如果还没做 13 闪判定）

**先做这个！它决定"这条路通不通"：**
```
烧 tools/uart_boot_probe/uart_boot_probe.ino
接 GND + GP28→相机RX
拔电池 → 插入电池（相机上电）
看指示灯:
  ★ 13 次短闪 ⇒ 打进了 BootROM 串行启动 ✓✓✓ ⇒ 可以灌 payload
  正常开机 / 毫无反应 ⇒ 没打中 ⇒ 换脚 / 改方波时序（200/250/300us）
  别的闪法 ⇒ 记录下来（可能是别的错误码）⇒ 换脚
⚠️ 失败无害：拔电池即恢复
```

## 五、安全保证（payload 设计保证）

```
✅ 找不到 ld.so.preload ⇒ 零字节写入（相机完全不变）
✅ 重复灌 ⇒ 幂等（size 已 0 就不再写）
✅ 写后读回校验；失败会尝试恢复原值
✅ 只改 1 个字节（size 字段最低字节）
✅ 全程不碰 boot 分区（只动用户区 nflasha10）
✅ 1 秒长闪 + 3 快闪确认 payload 已启动
✅ 结果 LED 无限重复播报，错过一轮也不用重新灌入
```

## 六、禁止事项

```
✗ 不要磨主板（等确定答案）
✗ 不要用 5V 推挽驱动相机 RX（3.15V OPEN_DRAIN）
✗ 不要往相机注入外部电源
✗ 不要修改 payload 的落点/栈地址（已按 BootRAM 证据设定）
✗ 不要在没看到 13 闪的情况下反复灌（先确认 BootROM 能进串行启动）
```
