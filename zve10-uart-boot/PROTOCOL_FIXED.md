# 2026-10-22 关键突破：记录协议修正 + 二级加载器

## 一、记录协议（此前一直是错的）

**正确格式（来自 A7C 笔记，实测确认）**

```python
[SET_UNLOCK(0x8CB102DC)]
  MEM_WRITE 0xFE020000+off   ← 每块 ≤4086 B
  ...
[SET_ENTRY(entry)]
[SET_UNLOCK(0x8CB102DC)]
```

**关键点**
- 组首与组末必须是**同一 type**（都是 SET_UNLOCK），ROM 靠它关组
- **不能**用 END_MARKER(0x0123) 当组首 / 组末；否则关组时 flag 为 0 → `0x2004`（1 长 4 短）
- 记录长度字段 = `10 + len(payload)`（含 header，不含 CRC）
- 记录之间留 14.4 ms；组内不允许 >293.6 µs 的静默（载波必须持续翻转）
- 载波开启后等 0.5 s 再发第一条记录
- 整组必须 < 1.45 s ⇒ 单次最多约 6 KB 载荷

**修正前**：我们用了 END_MARKER 当组首，payload 极少能执行
**修正后**：380 B 测试程序立即成功（1 秒长闪 + 3 快闪 + 慢闪）

## 二、二级加载器（绕过 6 KB 限制）

```
第 1 段（≤6 KB，走串口启动）：接收器 payload
   · 关看门狗、自检闪灯
   · 自校准 UART 接收（用起始位宽度校准每位时间，不依赖 CPU 频率）
   · 同步魔数 AA 55 AA 55
   · 多段协议：重复 [addr(4) len(4) data] ，addr=0xFFFFFFFF 结束，再读 entry(4)
   · 每写完一段闪一下，最后跳 entry
第 2 段（不限大小）：主机用 CMD_BLOB 直接流式发送任意长度数据
```

**已实测**：接收器启动（短闪）→ 380 B 程序接收（短闪）→ 跳转执行（1 秒长闪 + 3 快闪 + 慢闪）✅

## 三、RP2040 固件需要两种载波

| 阶段 | 载波 | 原因 |
|---|---|---|
| 记录组 | **翻转**（约 4 kHz） | ROM 需要边沿同步；组内不能有静默 |
| 数据流 | **空闲高电平** | 接收器需要干净线路 |

固件 `uart_boot_dual.uf2` 支持两者：命令行 `CMD_RAW(0x0C)` 切换到空闲载波。
