## 控制器基址：0xF0304000（与标准 SDHCI 同址）+ 索尼厂商扩展
字面量证据：
- 0xfe04fa64 = 0xF03044FC  ← 厂商寄存器
- 0xfe04fa68 = 0xF030403E  ← Host Control 2（bit7 = 1.8V 信令使能）
- 0xfe04fa6c 附近还有 0xF0304204

## 已提取的寄存器访问（0xfe04f746 区间，reset/deinit 段）
```
0xF03044FC : bic #2                 (清 bit2)
0xF030403E : bic #0x80              (关 1.8V 信令)
0xF030403E : 读改写
0xF0304204 : 读改写 ×3
0xF030403E : 读改写 ×2
0xF0304204 : ldrb/strb/ldr/str 序列
```
⇒ 这是"复位/去初始化"路径。初始化（置位）路径在调用子函数中：
   0xfe053818 / 0xfe052b4a / 0xfe052504 等

## 2026-10-22 03:25 补充（寄存器使用频率）
loader 中引用的 0xF030xxxx 字面量：
```
0xF030402C  ×17   首处 0xfe0527d4   ← CLKCTL（时钟控制/稳定轮询），最核心
0xF0304204  ×3    首处 0xfe04f98e   ← 厂商寄存器
0xF030403E  ×2    首处 0xfe04f952   ← Host Control 2（1.8V）
0xF03044FC  ×2    首处 0xfe04f948   ← 厂商寄存器
```
⇒ 初始化核心在 0xF030402C（CLKCTL）：0xfe0527c8 是时钟配置函数
   （读 0x2C → 清 bit2 → 延时 → 写回 → 再轮询）
⇒ 我们的 payload 目前时钟写法过于简化，缺少：
   · 轮询 0x2C 的稳定位
   · 厂商寄存器 0x4204 / 0x44FC 的配置
   · 1.8V 信令（0x3E bit7）的设置顺序

## payload 需要的完整序列（从 loader 抄）
1. 0xF030402C: 读改写（清 bit2）、延时、写回
2. 0xF03044FC: 清 bit2
3. 0xF030403E: 清 bit7（之后高速模式再置位）
4. 0xF0304204: 读改写 ×3
5. 时钟稳定轮询 0x2C
6. 之后才 CMD0/CMD1

## 2026-10-22 03:45 SDHCI 实测进展（重要）
已验证可跑通（曾一次性跑到第 10 阶段后进入慢闪）：
  CAP → SWRST → 时钟(先关后开+400kHz+稳定位轮询) → 电源 → CMD0
  → CMD1(重试循环) → CMD2(0x05) → CMD3(0x0E) → CMD7(0x0F) → CMD17(0x1E)

关键修正记录：
  · CMD0 必须 0x0000（bit4 数据位不能置，否则控制器挂死）
  · CMD1 用 0x02(R1) + 重试直到 RESP bit31=1
  · CMD2 = R2 + CRC = 0x05；CMD3 = 0x0E；CMD7 = 0x0F；CMD17 = 0x1E
  · 时钟：先清 CLKCTL bit2 → 设 400kHz → 轮询 bit1 → 再置 bit2
  · 不要访问厂商寄存器 0xF0304204 / 0xF03044FC（会导致异常）
  · 读数据端口 0x20 前必须等 INT_STATUS bit5(数据就绪)，否则挂死

当前不稳定点：CMD3 之后 CMD7 有时挂（RCA/卡状态），或更早阶段随机停。
下一步：固定 RCA=0x00010000；CMD7 用 0x0E(R1)；每步加重试与超时；
       必要时在 CMD2 后加 mdelay 等待卡内部状态稳定。
