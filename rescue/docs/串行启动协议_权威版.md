# BootROM 串行启动协议 —— 权威版（以源码原文为准）

> ⚠️ **本文件纠正了一个曾发生的错误**：早期自检时把 `MEM_WRITE` 记成 `0x0000`、
> `SET_UNLOCK` 记成 `0xfffe` —— **全错**。若真机灌入时用错，payload 根本不会被写入。
> 以下常量全部摘自 `ILCE-7M4-RE/scripts/push_payload.py` **源码原文**。

## 1. 命令类型（`SerCmd`）

```python
class SerCmd(enum.IntEnum):
    """
    Anything that isn't 0 or ffff is interpreted as a memory write command
    A session is ended by re-sending the first command
    We send END_MARKER first, as a dummy write with empty payload, so
    it can be later used as an end command.
    """
    SET_UNLOCK = 0x0000
    MEM_WRITE  = 0x0001
    END_MARKER = 0x0123
    SET_ENTRY  = 0xffff
```

| 常量 | 值 | 语义 |
| --- | --- | --- |
| `SET_UNLOCK` | **`0x0000`** | 解锁码（**特殊值，不是内存写**） |
| `MEM_WRITE` | **`0x0001`** | 内存写（**任何非 0 / 非 0xFFFF 的值都算内存写**） |
| `END_MARKER` | **`0x0123`** | 空 payload 的哑写；**重发第一条 = 会话结束** |
| `SET_ENTRY` | **`0xFFFF`** | 加载并跳转；**value 字段 = 入口地址** |

**★ 关键理解：`END_MARKER` 本身也是一条内存写（type=0x0123 落在"非 0/非 FFFF"范围内），
只是 payload 为空 ⇒ 实际效果是"无害哑写"。协议靠"重发第一条命令"来表示会话结束。**

## 2. 帧格式

```python
def record(rtype, value, payload=b""):
    body = struct.pack("<IHI", 10 + len(payload), rtype, value) + payload
    return body + struct.pack("<I", zlib.crc32(body))
```

```
┌─────────────┬───────────┬──────────────┬──────────────┬────────────┐
│ u32 len     │ u16 type  │ u32 value    │ payload      │ u32 crc32  │
│ = 10+plen   │ SerCmd    │ 目标地址/入口 │ 最多 4086 B  │ 覆盖前段    │
└─────────────┴───────────┴──────────────┴──────────────┴────────────┘
  小端 · len 不含 CRC · CRC 覆盖 [len..payload]
```

| 参数 | 值 |
| --- | --- |
| `LOAD_ADDR` | `0xFE020000` |
| `MAX_RECORD_PAYLOAD` | 512（脚本保守值；**真实上限 4086**） |
| `TRANSMIT_START` | 0.5 s |
| `RECORD_GAP` | 0.0144 s |
| 波特率 | 48000 |

## 3. 记录序列（§boot_script）

```
① record(END_MARKER 0x0123, value=0)                      ← 起始哑写
② for off in 0..len(payload) step 512:
     record(MEM_WRITE 0x0001, value=LOAD_ADDR+off, chunk)  ← payload
③ [unlock bypass]
     record(MEM_WRITE 0x0001, value=0xFE02F398,
            0xdeadbeef + (crc32(0xdeadbeef) ^ 0xFFFFFFFF))  ← 覆盖期望值
④ record(SET_ENTRY 0xFFFF, value=入口地址)                  ← ★ 加载并跳转
⑤ record(SET_UNLOCK 0x0000, value=unlock_code)              ← ★ 0x0000 才是 SET_UNLOCK
⑥ record(END_MARKER 0x0123, value=0)                       ← 结束（重发第一条）
```

## 4. `aux_fix` 实际记录流（bypass 版 19 条 / 7,018 B）

```
#    type    value       payload  说明
 0   0x0123  0x00000000     0 B   起始
 1   0x0001  0xFE020000   512 B   payload[0x000..0x200]
 2   0x0001  0xFE020200   512 B   payload[0x200..0x400]
 ...
13   0x0001  0xFE021800   512 B   payload[0x1800..0x1A00]
14   0x0001  0xFE021A00    88 B   payload 尾部
15   0x0001  0xFE02F398     8 B   unlock bypass
16   0xFFFF  0xFE020000     0 B   SET_ENTRY → 跳 0xFE020000
17   0x0000  0xDEADBEEF     0 B   SET_UNLOCK
18   0x0123  0x00000000     0 B   结束（CRC 与 #0 完全相同 ✓）
```

**传输时间 @48000 baud：≈1.46 s（不含 gap）· ≈1.74 s（含 gap）**

`-u 0x2CF25621` 变体为 18 条 / 6,996 B，不包含 bypass 写入记录。

## 6. unlock code（重要未验证项）

| 机型 | unlock code | 备注 |
| --- | --- | --- |
| a7M4 (CXD90057) | 默认 **bypass**（写 `0xdeadbeef` 到 `0xFE02F398`） | 上游默认路径 |
| A7IV | `0x2CF25621` | 源码注释明确 |
| **ZV-E10 (CXD90045)** | **未知** | 未在固件中找到；先用 a7M4 的 bypass 试 |

**⚠️ `0xFE02F398` 是 a7M4 BootROM 特定栈偏移（注释：*"may vary depending on the boot mode"*）
⇒ CXD90045 可能不同。若第 1 次无反应，需要试其它偏移或找真正的 unlock code。**
