# ZV-E10 救砖：A7M4 fastboot 路线（扒自上游 ✓）

## 0. 结论先说
上游 a7M4 的"fastboot"**不是普通 USB fastboot** ✗，而是：
**BootROM 秘密串行启动模式** ⇒ 灌 payload ⇒ 相机端建立 **USB fastboot** ✓
⇒ **完全不依赖相机固件** ✓✓ ⇒ 正好救"系统起不来" ✗✓
⇒ 而且：**你大佬测到的那根 RX，就是这条路的入口** ✓✓

## 1. 第一步：2 分钟判定（不需要 payload ✓✓ 最关键）
用上游的**探测程序**：`tools/uart_boot_probe/uart_boot_probe.ino`
```
接线: RP2040 GP27 → 相机 RESET 线 ; GP28 → 相机 RX ; GND ↔ GND
开机:
   ★ 出现【13 次短闪】⇒ 错误码 0x100D(奇偶校验错) ⇒ 
        【证明打进了 BootROM 的串行启动代码】⇒ ZV-E10 有这条路 ✓✓✓
   正常开机/别的异常 ⇒ 没打中（可重试）✗
⚠️ 上游明确: 相机"死了"别慌，【拔电池即恢复】✓ 此步无害 ✓
```

## 2. 第二步：搭正式桥（RP2040）
`tools/uart_boot/`（RP2040 + PIO，open-drain）
```
MULTI_TX=GP28 → 相机 RX · MULTI_RX=GP29 ← 相机 TX · MULTI_RST=GP27 → RESET · GND↔GND
LINK_BAUD=48000 · RESET_PULSE_US=10 · STARVE_MS=1200
电平: 相机 multi 串行 ≈3.15V；RP2040 3.3V ⇒ 【OPEN_DRAIN】✓ 不要 5V 推挽 ✗ 不要注入电源 ✗
板: waveshare_rp2040_zero（上游默认）✓ 首次刷固件按住 BOOTSEL ✓
```

## 3. 第三步：送 payload ⇒ USB fastboot
`scripts/push_payload.py` + `payloads/fastboot/`
```
成功后 USB 上出现 fastboot 设备，可执行:
   fastboot oem partition              # 列分区
   fastboot oem partition dump <name>  # ★ 备份（先备份！）
   fastboot flash <分区> <文件>        # ★ 写回 ⇒ 修 /etc(nflasha10) 就靠它
   fastboot oem peek/poke/exec         # 内存读写/执行 ⇒ 还能救更多
```

## 4. ⚠️ 诚实提示：兼容性
```
· 上游 payload 是给 【CXD90057 Mira / CXD90058 Cetus】写的 ✗
· ZV-E10 是 【CXD90045】⇒ payload 【不能直接用】✗（内存映射/SDHCI/USB PHY 都不同）
· 但: BootROM 基址都是 0xffff0000 ✓（同族 ✓）⇒ 探测【值得先做】✓
· 若探测到 13 闪 ⇒ 需要【为 CXD90045 移植 payload】✗（工作量不小，但有上游代码当模板 ✓✓）
· 若探测不到 ⇒ 这条路对 ZV-E10 不成立 ✗ ⇒ 回到 UART/送修
```
