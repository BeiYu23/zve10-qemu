# CXD90045（ZV-E10）BootROM 串行启动 —— 可行性分析

> 2026-10-17 · 由 QEMU 侧辅助对话整理（供真机执行参考）

## 1. ★ 硬证据：CXD90045 的 BootRAM 与 a7M4 同址

**内核源码 `arch/arm/mach-cxd900x0/include/mach/platform.h`：**
```c
#define CXD900X0_ESRAM_BASE   0xfe000000
#define CXD900X0_ESRAM_SIZE   SZ_16M
#define VA_BOOTRAM            IO_ADDRESS(CXD900X0_ESRAM_BASE)   /* ★ 名字就叫 BOOTRAM */
```

| 项 | CXD90045 (ZV-E10) | CXD90057 (a7M4) | 是否一致 |
| --- | --- | --- | --- |
| BootROM | `0xFFFF0000` | `0xFFFF0000` | ✅ |
| BootRAM / ESRAM | `0xFE000000`（16MB） | `0xFE000000` | ✅ |
| payload 落点 | `0xFE020000`（推定） | `0xFE020000` | ✅ |

**⇒ 同族同布局 ⇒ 串行启动的落点/入口可以沿用 `0xFE020000`（最终以物理探测为准）。**

## 2. 串行启动协议（来自上游 `push_payload.py`）

```python
MAX_RECORD_PAYLOAD = 512          # 每条记录最多 512B 数据
LOAD_ADDR = 0xFE020000

def record(rtype, value, payload=b""):
    body = struct.pack("<IHI", 10+len(payload), rtype, value) + payload
    return body + struct.pack("<I", crc32(body))     # 每条带 CRC32

boot_script():
    END_MARKER(0)                                   # 起始
    for off in 0..len(payload) step 512:
        MEM_WRITE(0xFE020000+off, payload[off:off+512])
    [unlock bypass] MEM_WRITE(0xFE02F398, 0xdeadbeef+CRC)
    SET_ENTRY(0xFE020000)                           # 加载并跳转
    SET_UNLOCK(0xdeadbeef)
    END_MARKER(0)
```

| 常量 | 值 |
| --- | --- |
| `END_MARKER` | `0x0123` |
| `MEM_WRITE` | `0x0000` |
| `SET_ENTRY` | `0xFFFF` |
| `SET_UNLOCK` | `0xFFFE` |

## 3. ★ unlock code 是机型常量（重要）

```python
ap.add_argument("-u", "--unlock-code", ..., default=None)
#                      源码注释原文: "0x2CF25621 for A7IV"
```

| 机型 | unlock code |
| --- | --- |
| a7M4 (CXD90057) | 默认走 **bypass**（往栈上写 `0xdeadbeef` 覆盖期望值） |
| A7IV | **`0x2CF25621`**（显式提供） |
| **ZV-E10 (CXD90045)** | **未知** |

**已在 ZV-E10 全部固件分区 + WBI(nflasha5) 里搜索 `0x2CF25621` ⇒ 未找到 ⇒ 不是固件常量。**

**⚠️ bypass 的栈偏移 `0xFE02F398` 是 a7M4 BootROM 特定值（注释：*"may vary depending on the boot mode"*）⇒ CXD90045 可能不同。**

## 4. ★★ 探测只需一根线（RESET 可用拔电池代替）

`uart_boot_probe.ino` 全文只做两件事：
```cpp
① 拉低再释放 RESET（抓 BootROM 窗口）
② 持续发方波：233us 高 / 233us 低（≈2145 baud，故意发垃圾制造奇偶错）
```
且其注释写明：**"If your camera dies, don't panic, just pull the battery"** ⇒ **拔电池就是有效复位**。

### ⇒ ZV-E10 的「拔电池时序法」（只需 RX + GND）

```
① 相机装电池但不开机
② RP2040 开始持续发方波（uart_boot_probe 的 for(;;)）
③ 装电池 / 按开机键 ⇒ 相机上电 ⇒ BootROM 在串行窗口"听到"方波
④ 判定:
     ★ 13 次短闪 ⇒ 错误码 0x100D（奇偶错）⇒ 打进了 BootROM 串行启动 ✓✓✓
     正常开机 / 其它错误 ⇒ 没打中 ⇒ 重试（换时机/多次）
⑤ 失败无害 ⇒ 拔电池恢复 ✓
```

**⇒ 物理要求降到最低：只需碰到 RX 一个点 + GND。**

| 阶段 | 内容 | 需要 RESET？ |
| --- | --- | --- |
| 阶段 1（判定） | 方波 @ ~2145bps ⇒ 看 13 闪 | ❌ 不需要（拔电池代替） |
| 阶段 2（灌 payload） | 48000bps + BLOB 记录 | 建议有；也可"持续发 + 手动上电" |
