## 二、今晚操作单（按顺序，每步有判据）

### 第 0 步：接好硬件

- Pico 插电脑；相机接 24pin 小板；电池在位
- 确认：`ls /dev/ttyACM0` 存在、`lsusb | grep 2e8a` 有 Pico

### 第 1 步：★ 抓真机基准（最高价值，只读）

相机**正常开机、UI 出现在屏幕上**之后，从服务模式 shell 进去，跑：

```sh
sh /tmp/z10_capture.sh          # 脚本在 tools/z10_capture.sh
```

产出 `/tmp/z10cap.tgz`，里面最关键的三样：

| 文件 | 回答什么问题 |
|---|---|
| `proc_cmdlines.txt` | ★ **真机 `im.elf` 的 `target=` 是什么**（QEMU 侧现在用 `target=qemu`，真机值未知——这会改变装载的库集合） |
| `ui_maps.txt` | ★ 真机 UI 起来时，哪些 `view*.uxc` / 库真的被映射 |
| `alog.bin` | ★ App 自己的日志（384 KB），直接看它走到哪一步 |

判据：`alog.bin` 非零（`tr -d '\000' | wc -c` > 0）；`ui_maps.txt` 里出现
`view*.uxc`。

### 第 2 步：定 Darwin 的 XCS 引脚（解 5~9 分钟会话限制）

在同一个服务 shell 里：

```sh
/usr/bin/gpioctrl.elf dump
```

找被驱动、上电高电平（XCS 低有效）的那条线，以及 `GPIO_SB_*_XCS*` 别名。
拿到引脚后才能在 payload 里实现 `oem darwin`（SIO 通道 0 / `0xF1005000`）。

判据：输出里有 XCS 别名的引脚清单。

### 第 3 步（可选，但后续省很多事）：启用 telnet

```sh
/usr/bin/sndcmd.elf --ulogio "telnet up"
reboot -f
```

重启后连相机 IP（端口待确认，先试 23；`netstat -ltn` 或 PC 扫描）。
之后所有调试都不用插线——包括以后抓 alog、跑 gpioctrl。
（注意：这一步会写 `/setting/ULOGIO.BIN` 的 TELN 标志，属于可逆的配置写入。）

### 第 4 步：把第 1 步的结果发给 QEMU 侧

QEMU 对话（session-41b33827）正在等这三个数据。他们有真机值才能判断
`target=` 是否用错了。
