# ZV-E10 QEMU 移植 —— 交接说明（2026-10-25）

## 一、当前结论（一句话）
**显示链路已完全打通并可复现（满屏彩条）；绘制层 shim 已就绪；
唯一剩余瓶颈是 App 的 `initializeConfig` 不返回**（进程一直存活、线程全在等待、
未走 exit(0) 失败路径、load 走的是 im.elf 自带 OnDemandLoader）。

## 三、已验证事实（不要再重复验证）
1. 老菜单启动链完整：init → bootin.elf → sen.elf → launch_shell.elf → net_cmdd.elf → ash → im.elf
2. `/dev/mem` mmap 0x20312000 可写，写什么屏幕显示什么（几何见上）
3. libObj 基址 0x05E82000（每次运行可能不同，用 MAPD 现取）
4. `dmp_allocator_lib_init`（libObj+0x6BCB58）里 `osal_wai_sem_tmo(0x018004B5,-1)` 是"只等不发"的信号量；
   但放行它并不能让 initializeConfig 返回
5. 所有 App 线程停留在 libc/libpthread 等待点（非死锁、非忙等）
6. im.elf 进程 96 秒全程存活 ⇒ 未走 `exit(0)` 失败路径
7. App 不使用 libc `dlopen/dlsym`（interpose 0 命中）⇒ 走 im.elf 自带 OnDemandLoader
