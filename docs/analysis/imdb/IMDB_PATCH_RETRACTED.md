# ⚠️ 补丁版 libIMDB 作废声明（含缺陷分析与结论撤回）

> 真机侧复审发现三条缺陷，其中两条致命。**`libIMDB_patched.so` 不得使用。**
> 本文记录缺陷、根因、以及被我错误引用的结论的撤回范围。

## 一、缺陷（已逐条反汇编复核）

### 缺陷 1【致命】`mount` 第 5 参数传错

**原代码：**
```asm
movs r6, #0
push {r6}          ← 按 C 调用约定传第 5 参
movs r7, #21       @ __NR_mount
svc  0
add  sp, #4
```

**ARM EABI 系统调用的参数在 `r0..r6`，不是 `r0-r3 + 栈`。**
`mount(dev, dir, type, flags, data)` ⇒ `data` 必须在 **`r4`**。

**⇒ 该写法让 `r4` 保持原值，而 r4 被用作 image fd ⇒ 内核收到的是"fd 当指针"。**
**⇒ `mount` 必然失败或行为未定义。**

### 缺陷 2【致命】尾调用使用绝对地址

```asm
ldmia.w sp!, {r4,r5,r6,r7,lr}
movw  r3, #14045   ; 0x36dd
bx    r3
```

**`libIMDB.so` 是 `ET_DYN` ⇒ 运行时有 load bias ⇒ `0x36DD` 是文件内 vaddr。**
**⇒ `bx` 跳到未映射地址 ⇒ 进程崩溃。**

**正确写法（PC 相对反推 load bias）：**
```asm
adr  r3, here
ldr  r1, =0x6998      @ 编译期 vaddr，作数据常量使用
sub  r3, r3, r1       @ load bias
add  r3, #0x36DC
orr  r3, r3, #1       @ Thumb 位
bx   r3
```

### 缺陷 3【中等】两次 `bind` 无返回值检查

**失败时静默继续，最终尾调用原 init ⇒ 装配无效但无提示。**

## 二、结论撤回范围

| 之前的说法 | 状态 |
|---|---|
| "补丁全部验证通过" | ❌ **撤回**（只验证了字节写入，未验证指令语义）|
| "race 无害" | ❌ **撤回**（"不破坏已加载库" ≠ "时序满足 dlopen 依赖"）|
| "拔卡可回 stock" | ❌ **撤回**（preload 在动态链接阶段生效，早于 safemode 逻辑）|
| 子进程 `/proc/self/maps` 自检 | ❌ **撤回**（子进程看不到父进程后续 dlopen）|
| 镜像内容不含 flash 写入逻辑 | ✅ **仍成立**（基于镜像内容实测，与补丁无关）|
| 各分区相互独立、原厂 dump 齐全 | ✅ **仍成立** |
| **"变砖风险极低"这一总结** | ⚠️ **暂停使用**（待全面审计完成）|

## 三、错误分类与根因

| # | 错误 | 根因 |
|---|---|---|
| 1 | mount 参数按 C 约定传栈 | **把 C 调用约定套到系统调用，未对照 ARM EABI syscall ABI** |
| 2 | 尾调用用绝对 vaddr | **忽略 ET_DYN load bias，把"文件偏移"当"运行时地址"** |
| 3 | 声称补丁验证通过 | **只验证"写入正确"，未验证"语义正确" —— 两个不同层次** |
| 4 | 说 race 无害 | **混淆"不破坏已加载库"与"时序满足依赖"** |
| 5 | 用子进程 maps 自检 | 概念性错误 |

**★ 最该记住的是第 3 条：边界检查、PT_LOAD 检查、字符串地址逐条验算，
全都是"字节写对了"，没有一条回答"这些指令执行起来对不对"。**

## 四、★ 方案本身的架构风险（与补丁无关，需在审计中列出）

**`/setting/mode/preload` 位于内部 eMMC。若其中某库导致进程卡死/崩溃：**

```
失效模式             恢复手段
──────────────────────────────────────────
新菜单能起但不正常    拔卡 / 改 preload 文件（需 shell）
进程卡死 / 崩溃       ★ 必须 fastboot 才能改 /setting/mode/preload
```

**⇒ 该方案天然带"启动环回依赖 fastboot"的恢复路径。**
**⇒ watchdog 思路本身也要在早期执行，存在循环依赖。**
