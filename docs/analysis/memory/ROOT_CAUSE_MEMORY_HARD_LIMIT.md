# 根本原因：新菜单的 `.bss` 超过相机总内存 —— 物理上装不下

> 结论：**不是配置问题，不是参数分叉，是内存硬限制。**
> ZV-1F 与 ZV-1M2 两个供体**都装不下**。

## 一、决定性数据

| 库 | FileSiz | MemSiz | **★ BSS** |
|---|---:|---:|---:|
| **ZV-E10 `libObj.so`（单体）** | 21,304,104 | 21,565,052 | **260,948 (0.2 MiB)** |
| **ZV-1F `appFw.so`** | 53,187,072 | 127,894,120 | **74,707,048 (71.2 MiB)** |
| ZV-1F `libObj.so` | 3,928,296 | 3,993,008 | 64,712 (0.1 MiB) |
| **ZV-1M2 `appFw.so`** | 64,270,744 | 140,420,392 | **76,149,648 (72.6 MiB)** |
| ZV-1M2 `libObj.so` | 3,930,152 | 3,994,864 | 64,712 (0.1 MiB) |

## 二、与相机实测内存对比

```
相机 MemTotal  : 125.8 MiB   （真机 /proc/meminfo）
相机 AnonPages :  57.4 MiB   （已占、不可回收、无 swap）
```

| 方案 | BSS 需求 | 57.4 + BSS | 判定 |
|---|---:|---:|---|
| 老菜单（E10 原厂） | 0.2 MiB | **57.6 MiB** | ✅ 余量充足 |
| **ZV-1F 供体** | 71.3 MiB | **128.7 MiB** | ❌ **超过 125.8** |
| **ZV-1M2 供体** | 72.7 MiB | **130.1 MiB** | ❌ **超过 125.8** |

**⇒ 连 `.text` 常驻页、uxengine arena 堆、以及已有的 30 MB Mapped 都还没算进去，
仅 `.bss` 一项就已经超过物理内存总量。**

## 三、为什么 `.bss` 是硬约束

```
.text / .rodata  → 文件页，可按需换入、可丢弃重读（有 /usr 这个只读 ext2 作回读源）
.bss             → 零填充匿名页，**一经触碰就永久占用**（无 swap，无法回收）
```

**⇒ appFw 的 72.6 MiB bss 是 UI 框架的静态缓冲区（arena、缓存、资源池），
启动时就会大面积触碰 ⇒ 必然撞上物理内存上限。**

**⇒ `overcommit_memory = 1`（永远允许）⇒ `dlopen` 本身不报错，
失败发生在缺页时 ⇒ OOM kill 或线程静默死亡。**

**⇒ 这完美解释：无 UI、无日志、无明确崩溃信息、而刷回老菜单立刻正常。**

## 四、为什么老菜单毫无压力

**E10 的 `libObj.so` 有 21 MB 但 **BSS 只有 0.2 MiB** —— 几乎全部是可换出的代码与只读数据。**

**⇒ 老菜单的实际物理占用极小，与 21 MB 的文件大小无关。**

**⇒ 这也是为什么我此前靠"文件大小 61 MB vs 21 MB"估算时方向对但不够硬 ——
真正的杀手是 **BSS**，不是文件大小。**

## 五、⇒ 由此推出的几个结论

**① 换供体没有出路**
ZV-1F 与 ZV-1M2 的 appFw bss 分别是 71.2 / 72.6 MiB，都超。
**⇒ 换回 ZV-1F 也一样装不下。**

**② ZV-1F / ZV-1M2 必然有更多可用 RAM**
它们的 `/usr` 分区分别是 500 MB / 700 MB（E10 只有 300 MB）⇒ 更高配置硬件。
**⇒ 「新菜单在同代机型上能跑」不能推出「在 E10 上能跑」。**

**③ 唯一的理论出路（都很重）**
```
· 减小 E10 的 memrsv 预留，把更多 RAM 给 Linux
    KEMCO.TXT 显示: mem=1G@0 + 175MB 预留 + 680MB 预留 ⇒ 只剩 125.8 MB
    要从 125.8 提到 ~160+ MB 才够（含 text/arena 余量）
    ⇒ 需改 bootloader/cmdline，且 CP 很可能真的需要那些预留区
· 拆分 appFw（不现实，无源码）
· 放弃"新菜单上 ZV-E10"
```

## 六、这个结论的可复现验证

**完全静态、无需上机：**
```bash
readelf -lW <任意 appFw/libObj> | awk '$1=="LOAD"{f+=$5;m+=$6} END{print "BSS="m-f}'
```
**对比 `MemTotal`（真机 125,796 kB）即可。**

**⇒ 与之前所有"运行时探针"相比，这条是**硬上界**，不依赖任何运行时行为。**
