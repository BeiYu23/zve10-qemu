# 真机内存布局（从 `/setting/KEMCO.TXT` 原件 + `/proc/meminfo` 快照核算）

> 本文给两条线共用。**所有数字都来自真机原件，不是推测。**

## 一、cmdline 里的内存声明与保留

```
mem=1G@0
memrsv=1M@0
memrsv=0x8000@0xF00000
memrsv=0x1A5E000@0x02E68000
memrsv=0xAEEB000@0x0A915000
memrsv=680M@0x15800000:uc
mem=256M@0x80000000@1
memrsv=256M@0x80000000:uc        ← 第二个 bank 整段保留
```

- 声明合计 **1,280 MB**
- 保留合计 **1,138 MB**（含 bank1 全部）
- 推算可用 ≈ **129 MB**

**实测 `/proc/meminfo`：`MemTotal 128,796 kB`、`MemFree 2,904 kB` ✅ 完全吻合**

## 二、bank0 的可用 / 保留分布

| 区间 | 大小 | 性质 |
|---|---:|---|
| `0x00000000-0x00100000` | 1.0 MB | 保留 |
| `0x00100000-0x00F00000` | 14.0 MB | **可用** |
| `0x00F00000-0x00F08000` | 32 KB | 保留 |
| `0x00F08000-0x02E68000` | 31.4 MB | **可用** |
| `0x02E68000-0x048C6000` | 26.4 MB | 保留 |
| **`0x048C6000-0x0A915000`** | **96.3 MB** | **可用（普通 RAM）** |
| `0x0A915000-0x15800000` | 174.9 MB | 保留（GPU/CP 类 carve-out） |
| `0x15800000-0x40000000` | 680 MB | 保留（`:uc`） |

## 三、三个对 QEMU 线直接有用的结论

### 1. **129 MB 是保真的**

真机 MemTotal 就是 128,796 kB。QEMU 客人报 129 MB **不是缺陷，是与真机一致**。

### 2. **`0x08000000` 一带在真机上是【普通可用 RAM】**

崩点 `0x096000E4`(150MB)、`0x0A6000E4`(166MB) 都落在
`0x048C6000-0x0A915000` 这段**可用 RAM** 里，**不是**保留区。
⇒ "把窗口当保留区、用 `0x0A915000` 当边界"这条路会把窗口放进普通内存。
⇒ **真机的 carve-out 从 `0x0A915000` 才开始**，`0x08000000` 放窗口是 QEMU 侧的选择。

### 3. "物理范围外导致 abort" 不成立

QEMU 机器模型 `DDR0 = 1GB@0`，`0x096000E4` / `0x0A6000E4` **物理上都存在**。
崩的是**用户态虚拟地址未映射**，不是物理内存不存在。

## 四、窗口越界的定量规律（两次实测）

```
16 MB 窗口 (末=0x09000000) → 崩点 0x096000E4 = 末 + 0x6000E4  (6.00 MB)
32 MB 窗口 (末=0x0A000000) → 崩点 0x0A6000E4 = 末 + 0x6000E4  (6.00 MB)
```

**超出量恒为 6.00 MB** ⇒ 崩点**跟着窗口末移动**，不是固定绝对地址。

⇒ **单纯加大窗口不收敛**（41MB 窗口会把崩点推到末+6MB）。
⇒ 正确做法：**"映射 > 报告"**（实际映射大于向 App 报告的 size），
   且映射用**连续保留物理区 + 一次 `remap_pfn_range`**，不要 vmalloc 逐页（真机只剩 2.8 MB）。

## 五、固件里找不到"窗口基址/大小"的定义

- `0x08000000` 在 `appFw.so` / `libObj.so` 里出现极多，但绝大多数是
  `.rel.dyn` / `.ARM.extab` / `.data` 的**指令与重定位噪声**，不是地址表
- `appFw.so` `.data` 有唯一一处 `0x0A915000`，但**未 4 字节对齐**、上下文像压缩数据，
  **不能当边界定义**

⇒ **窗口基址/大小不是固件常量，而是驱动 mmap 与 App 协商出来的** ——
这也正好解释了"崩点跟着报告大小移动"。
