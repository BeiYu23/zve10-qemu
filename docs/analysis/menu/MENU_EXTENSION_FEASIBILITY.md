# 能否增加菜单显示 zvegisk 状态/模块列表/开关

## 结论

**三种方案，难度递增。推荐先做①的一半（静态状态显示），交互开关走文件。**

| 方案 | 可行性 | 工作量 |
|---|---|---|
| **① 改现有菜单项的文字** | ✅ **可行，已验证格式** | **小** |
| **② 增加新菜单项** | ⚠️ 技术可行 | 大（需 .uxc writer） |
| **③ 自绘制菜单** | ❌ 阻塞 | 等 GPU mmap |

---

## 一、✅ 方案①：改现有菜单项的文字（最可行）

### 字串表是纯 ASCII，直接可改

```
string_english_f.uxc   349,020 B
"Exit"    @ 0x58AB, 0x590C, 0x5A62, 0x5A77
"Select"  @ 0x596B
帮助长文本 @ 0x50000+ 区域
```

### 记录格式（实测解出）

```
id : 0x1EA0/0x1Bxx 标记 : 内容（UTF-8，含 PUA 行内标记）: 00 00

例：
00 a0 1b 1e | ee a0 81 | "To Rating Setting " | ee a0 8a | "Exit" | 00 00
05 a0 1b 1e | ee a0 81 | "Expand"
09 a0 1b 1e | ee a0 85 | "Select " | ee a0 81 | "Mark " | ee a0 8a | "Cancel"
```

**PUA 行内标记（UTF-8 编码在文本里）：**
```
U+E801 (ee a0 81)  普通文本样式
U+E805 (ee a0 85)  另一种样式
U+E80A (ee a0 8a)  按钮/高亮样式
```

**★ 这些标记会被引擎替换成按键图标或换色 —— 是 Sony 的提示文本格式。**

### ⚠️ 改长度会移位

**记录是 NUL 结尾的连续流，容器索引按 **ID** 不按字节偏移。
⇒ **改长度会导致后面所有记录的偏移变化** ⇒ 必须重算。

**★ 最安全：**等长替换**。**

**例：`"Exit"`（4 字符）→ `"ZVEG"`（4 字符）✓
     `"Select"`（6）→ `"ZVEGSK"`（6）✓**

### 能做到 / 做不到

| 能做 | 做不到 |
|---|---|
| **改菜单项的名字** | **显示动态内容（模块列表、计数）** |
| **显示静态字符串** | **点击后执行自定义动作（除非 hook）** |

**⇒ 所以方案①只能"改个名字"，不能"显示状态"。**

---

## 二、⚠️ 方案②：增加新菜单项

### 需要什么

```
① 新记录写进 string_*.uxc（或复用现有 ID）
② 新控件写进布局 .uxc（LayoutMaster_Menu.uxc / master_*.uxc）
③ 新 view 写进 global.xdb 的索引（313 条那套）
④ 动作 ID 必须是引擎认识的（96 个 scenario plugin 之一）
```

### 格式已知的部分

```
容器：magic 'uxc' + version 7 + stream version + resource_id + control + 稀疏索引
验证：302/302 文件、12,082/12,082 索引项全部有效

层级：header → u16 索引 → 4 字节对齐 body → 60 字节段描述符
      → 对象偏移表 → 14 字节对象头 → 属性
```

### 难点

- **需要写一个 `.uxc` writer（改记录数 ⇒ 重算全部偏移）**
- **`global.xdb` 索引方案两边不同（ZV-E10 313 条 vs ZV-1F 154 条）⇒ 加条目要理解它的引用语义**
- **动作必须是引擎认识的 ID，自定义动作需要 hook 动作分发**

**⇒ 可行但工作量大。**

## 三、❌ 方案③：自绘制

**阻塞在**没有 CPU 可见的像素面**：**

```
✗ /dev/fb0              ENXIO
✗ FBRM 高层 API          空桩
✗ /dev/mem + 物理地址     无可见帧缓存
✗ /dev/stream @0x20312000 描述符 + 压缩数据
✗ ttycons              是串口
✗ SUGILITE ioctl        17 个命令全是 4 字节标量控制
? /dev/dmpgles2 mmap    ★ 唯一未验证（只接受 512B/128KB/32MB）
```

**★ 若 GPU mmap 通了 ⇒ 才谈得上自绘。**

---

## 四、★★★ 推荐的折中路线

### 显示状态：用菜单文字（方案①的变体）

**把某个不显眼的菜单项**改名**成状态指示：**

```
"Exit" → "ZVEG"      （4 字符，等长）
```

**或者更好：替换**帮助文本**（长文本区域 0x50000+），
那里有空间写自定义说明。**

**⇒ 能做到"你打开帮助，看到 zvegisk 的说明"，但**不是动态状态**。**

### 模块开关：不走菜单

**因为菜单项的动作是引擎硬编码的，改它需要 hook 动作分发（未做 RE）。

**⇒ 现实方案：**

```
① 拔 SD 卡插电脑改 boot_mode（最简单，零风险）
② 用 agent 改文件（需要 USB）
③ ★ 未来的：hook 某个废弃菜单项的动作 ⇒ 点一下就切换
```

**★ ③ 需要先找到动作分发点。我们有 `libObj.so` 1953 个导出符号可查，
但那是新的 RE 工作。**

---

## 五、★ 一个更聪明的中间方案（值得考虑）

**不做菜单，做"开机提示"：**

**利用 `string_*.uxc` 的**帮助文本**区域，把 zvegisk 的状态写进去。
用户按某个键打开帮助，就能看到当前模式/模块列表。**

**优点：**
- **只需改字串表（等长替换，安全）**
- **不需要 .uxc writer**
- **不需要 global.xdb 编辑**
- **不需要 hook 动作**

**缺点：**
- **静态文本，不是实时状态**
- **要看状态得先知道去哪儿看**

**★★★ 但作为"可视化反馈"的第一步，这已经比"只能看日志"强很多。**

---

## 六、优先级建议

```
第 1 步【现在可做】改一个等长字串（如 "Exit"→"ZVEG"）验证字串表可改
        ⇒ 确认 UI 上真的变了（这是方案①②共同的前提）

第 2 步【低成本】把帮助文本换成 zvegisk 说明
        ⇒ 有了"文档入口"

第 3 步【中】hook 动作分发 ⇒ 支持"点击切换模块"
        ⇒ 需要 RE viewUnified2/libObj 的事件路径

第 4 步【大】.uxc writer ⇒ 增加真正的菜单项
        ⇒ 需要完整的格式理解 + 偏移重算

第 5 步【阻塞】自绘制 ⇒ 等 GPU mmap
```

**★★★ 第 1 步是**所有方案的前提**，而且成本极低 —— 建议立刻做。**
