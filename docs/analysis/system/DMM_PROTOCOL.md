# DMM 显存管理器协议（从 a7c2-re 的参考实现整理）

> 来源：`chocotan/a7c2-re` → `report/2026-10-17-qemu-native-camera/runtime/analysis/dmm-service.c`
> 该文件是带自测的完整参考实现（`DMM_SERVICE_SELFTEST_PASS`），不是推测。
> 本文整理其字段表，便于对照 ZV-E10 的 `dmm.ko` 使用。

## 一、基本规格

| 项 | 值 |
|---|---|
| GPU 物理基址 | `0x400000000`（4 GiB）|
| DMM 测试区物理地址 | `0x41E000000` |
| 单槽大小 | `0x80000`（512 KiB）|
| 池大小 | `0x100000`（2 槽 = 1 MiB）|
| 请求/应答长度 | 各 40 字节 |
| 分配魔数 | `0x63A` |

## 二、请求格式（40 字节）

| 偏移 | 类型 | 字段 |
|---:|---|---|
| `+0x00` | u16 | **op**（操作码）|
| `+0x04` | u32 | **magic = 0x63A**（ALLOC 时必校验）|
| `+0x08` | u32 | **handle** |
| `+0x14` | u16 | 被回显到应答 `+0x06` |
| `+0x16` | u16 | **option** |

## 三、操作码

| op | 名称 | option 约束 | 行为 |
|---|---|---|---|
| **0x20** | **ALLOC** | ≤ 1（1 = 返回 CP 地址）| 找空槽、generation++、清零 512 KiB、返回新 handle |
| **0x21** | **OPEN / AddRef** | ≤ 1 | `open_count++`（上限 255）|
| **0x22** | **CLOSE** | 必须 0 | `open_count--` |
| **0x23** | **FREE** | 0 或 2 | 清零 count 与 allocated；count 非 0 时返回 3 |

## 四、应答格式（40 字节）

| 偏移 | 类型 | 字段 |
|---:|---|---|
| `+0x00` | u16 | **`op \| 0x8000`**（回显并置 bit15）|
| `+0x02` | s16 | **转换后的状态码**（客户端读这个）|
| `+0x06` | u16 | 回显请求 `+0x14` |
| `+0x08` | u16 | 返回地址时置 1 |
| `+0x0A` | u16 | **原始状态码** |
| `+0x0C` | u32 | **handle**（ALLOC 成功时为新值）|
| `+0x10` | u32 | magic 回显 `0x63A` |
| `+0x18` | u32 | CP 地址低位 |
| `+0x1C` | u32 | CP 地址高位 |
| `+0x20` | u32 | 槽大小 `0x80000` |

## 五、Handle 编码（复用检测）

```c
slot->generation = (slot->generation + 1) & 31;   /* 5 位世代，回绕 */
handle = (slot->generation << 10) | index;        /* 10 位槽号 */
```

- 槽号 `index = handle & 0x3FF`
- 世代用于识别"已释放后被复用"的陈旧 handle

## 六、CP 地址换算

```c
cp_address = physical - 0x400000000ULL + index * 0x80000;
```

参考实现中 `physical = 0x41E000000`，因此：

| 槽 | CP 地址 |
|---:|---|
| 0 | `0x1E000000` |
| 1 | `0x1E080000` |

## 七、错误码映射（原始 → 客户端可见）

| 原始 | 含义 | 转换后 |
|---:|---|---:|
| `-4` | option 非法 | -4 |
| `-3` | magic 不是 `0x63A` | -3 |
| `-0x201` | 无空闲槽 | **-1** |
| `-0x105` | 槽号越界 | **-5** |
| `-0x205` | handle 不匹配（世代/槽号错）| **-5** |
| `-1` | 未分配 | -1 |
| `1` | CLOSE 时 count 已为 0 | 1 |
| `3` | FREE 时 count 非 0 | 3 |

## 八、参考实现的边界（作者自己标注）

- **只建模两个槽**，不是完整 DMM 池
- option 只支持 0/1，其余"超出本测试模型"
- FREE 的 option 只接受 0 和 2
- 自测覆盖：连续分配、池满、handle 无效、重复 free、AddRef/Close 配对、短请求

## 九、与 DMP 的区别（重要）

| 层 | 实体 | 状态 |
|---|---|---|
| **DMM（设备层）** | `dmm.ko` 的分配协议 | **★ 本文有完整规格** |
| **DMP（库内）** | `libObj` 的 `dmp_allocator_lib_init`，等 sem `0x18004B5` | 仍只有反汇编，未解 |

⇒ 对 ZV-E10 的启发：若 App 的显存请求最终落到 `dmm.ko` 一侧，
本文的字段/错误码/地址换算可直接用于写 stub，无需再猜。
若走的是 `libObj` 内部 DMP 库函数，则不适用。

## 十、可移植性提示

- 参考实现是 aarch64 / 64 位地址；ZV-E10 是 ARMv7 / 32 位
  ⇒ 应答里的 CP 地址高低位拆法需要按目标平台的指针宽度调整
- 魔数 `0x63A`、opcode 取值、错误码建议先用 ZV-E10 的 `dmm.ko` 静态核实再采用
