# 实测：`/dev/stream` @0x20312000 是描述符表，不是像素缓冲

> 方法：agent 在相机上只读 mmap `/dev/stream` 偏移 `0x20312000`（32 MB），
> 连续采样 10 次，期间用户打开菜单。**未写入任何数据。**

---

## 一、映射确实成功

```
open /dev/stream O_RDONLY = 3
mmap(len=0x2000000, off=0x20312000) = 0x41be000  OK
```

**⇒ `/dev/stream` 支持 mmap（不支持 read —— 早前探测 `read` 返回 ENOSYS）。**

---

## 二、★ 内容在 UI 绘制时**完全不变**

```
t=0 非零 153/8192 (1.87%)
t=1 非零 153/8192 (1.87%)
...
t=9 非零 153/8192 (1.87%)
峰值非零: 153
```

**⇒ 菜单打开、屏幕明显在显示内容时，这块 32 MB 一个字节都没变。**
**⇒ 它不是像素缓冲。**

---

## 三、★★★ 前 256 字节的布局

```
00000000 e3010000 08000000 00000000 00000000
c09ed701 00203180 00000000
18815980 ffffffff 6be8ffff 3828f935
00000000 00000000
30203180 30203180 38203180 38203180
40203180 40203180 f01c5980 e0213180
50203180 50203180 60a45980 60a45980
18815980 18815980 80865980 80865980
...

小端解：
  30203180 → 0x80312030
  38203180 → 0x80312038
  40203180 → 0x80312040
  50203180 → 0x80312050
  78203180 → 0x80312078
```

**特征：**
1. **大量 `0x80312000 + offset` 的指针** —— 而 CPU 虚拟基址是 `0x20312000`，
   差 `0x60000000` = **物理→内核虚拟映射偏移**
2. **sentinels**：`0xFFFFFFFF`、`0xFFFFE86B`、`0x35F92838`
3. **重复两次的指针对**（`30203180 30203180`）—— 典型描述符数组布局

**⇒ 这是**带物理指针的描述符表 / 命令环**。**

**★ 与 zv-e10-re 当年的独立结论一致：**
> "s4 is a descriptor table, not pixels. Its head holds kernel VAs... Following those pointers led to kernel code and klog format strings, not a buffer."

---

## 四、⇒ 对「帧缓存」判断的修正

| 假设 | 实测结论 |
|---|---|
| 0x20312000 是像素缓冲 | **❌ 是描述符表** |
| App 绘制 ⇒ 像素落在那里 | **⚠️ App 写的是命令，像素由 RTOS + 硬件生成** |
| 镜像该地址就能看到画面 | **⚠️ 镜像出来是命令字节** |

**显示管线：**
```
App 写描述符到 /dev/stream 映射区
        ↓
RTOS (BIONZ X / av-cam.bin) 解释描述符
        ↓
硬件：APL/AIC 合成 + XDMAC 搬运 + HME 编码
        ↓
私有 ldec 驱动 → 面板
```

**⇒ CPU 侧**没有**任何一步接触真实像素。**

---

## 五、对 QEMU 模型的影响

**现有 `bionz_streamfb` 把 0x20312000 当像素镜像 ⇒ 解出来的是**命令字节的伪彩色**，
不是 App 的真实输出。**

**★★★ 这为「整屏 0x5A5A」提供了另一种解释：**
**可能不是 VDF 初始化填充，而是**模型把描述符字节当像素解码**的产物。**
（见 `../system/FALSE_MILESTONE_5A_FILL.md`）

**建议：**
1. **不要再用 0x20312000 判断"App 画了没有"**
2. **判断依据改为：描述符内容是否更新**（计数器 / 序列号字段变化）
3. **真正的像素路径需要解描述符格式 + RTOS 命令引擎**（`av-cam.bin`）
