# ZV-1M2 (ZV-1 II) 与 ZV-1F / ZV-E10 对比

> 结论先行：**ZV-1M2 的固件无法用我们已有的密钥解开**，
> 但它与 ZV-1F 表现出【同一 crypter 代次】的特征，**很可能是同一平台的新一代**。
> **目前不能当供体用**（解不开）。

---

## 一、公开信息

| | ZV-1F | **ZV-1 II (ZV-1M2)** |
|---|---|---|
| 发布 | 2022 年 10 月 | **2023 年 5 月**（晚约 7 个月） |
| 镜头 | 定焦 20mm equiv | **变焦 18-50mm equiv** |
| 定位 | 入门 vlog | **更高端** |
| 最新固件 | 2.01 | **2.01**（2025-06-03） |

**ZV-1M2 固件功能（2.00 版新增）：**
- 拍摄信息布局支持横竖方向
- 显示 Wi-Fi 信号强度
- 固件更新通知
- **直传 Creators' Cloud**
- 提升稳定性

2.01：WPA/WEP 不再支持（强制 WPA2/3）

## 二、UFU 容器对比（实测）

| 项 | ZV-E10 (2.03) | ZV-1F (2.01) | **ZV-1M2 (2.01)** |
|---|---|---|---|
| 文件大小 | 372,454,920 | 443,505,056 | **627,176,840** |
| **FDAT 载荷** | 372,454,672 | 443,504,912 | **627,176,720** |
| 相对 ZV-1F | −16% | 基准 | **+41%** |
| UDID 条目数 | **23** | **10** | **7** |
| updater PID | `0x03E2` | `0x03E2` | **`0x03E2`** |
| CRC32 (DEND) | ✅ | ✅ | **✅ 已校验通过** |

### 2.1 USB PID 集合（机型代次指纹）

```
ZV-E10 (23):  0x448 0x47D 0xBFE 0xBFF 0xC01 0xC02 0xCA7 0xCA8
              0xBEE 0xBEF 0xCC9 0xCCA 0xC13 0xC14 0xD0D 0xD0E
              0xD11 0xD12 0xD28 0xD29 0xD94 0xD95 [+0x3E2 updater]

ZV-1F  (10):  0x448 0x47D 0xCAF 0xCB0 0xCAB 0xCAC 0xD24 0xD25 0xE06 [+0x3E2]

ZV-1M2  (7):  0x448 0x47D 0xD24 0xD25 0xE06 0xE7A            [+0x3E2]
              └──── 与 ZV-1F 完全相同的 5 个 ────┘   └新增┘
```

**⇒ ZV-1M2 的 PID 集合是 ZV-1F 的子集 + 一个新 PID（`0xE7A`）**
**⇒ 强烈指向【同一代次平台】，只是 USB 模式做了精简（23→10→7）。**

## 三、★★ 决定性测试：crypter 密钥

用前人恢复的 `CXD90045` 密钥（32 字节 AES）分别解三个包：

| 包 | 结果 |
|---|---|
| **ZV-E10 2.03** | ✅ **成功**：`UDTRFIRM` / `model 0x01030010` / `version 2.03` |
| ZV-1F 2.01 | ❌ 失败：`checksum mismatch: header says 0xcd0d, computed 0xf708` |
| **ZV-1M2 2.01** | ❌ 失败：`checksum mismatch: header says 0xa058, computed 0xdc8a` |

**⇒ ZV-E10 用 `CXD90045`（我们可解）；ZV-1F 与 ZV-1M2 都用【我们解不开的那一代】。**

**参照 `config.yaml` 里的 crypterName：**
```
ZV-E10   : CXD90045        ← 可解
ZV-1F    : CXD90045_k8     ← 解不开
ZV-E10M2 : CXD90057_k8     ← ARGO/ARM64
```

**⚠️ 注意：`_k8` 后缀在 ZV-E10M2（ARM64）上也出现 ⇒ `_k8` 是 crypter 代次，不是 SoC 标识。**
**真正区分 SoC 的是前缀 `CXD90045` / `CXD90057`。**

**⇒ 因此：ZV-1M2 到底是 `CXD90045_k8` 还是 `CXD90057_k8`，目前无法从固件本身判定。**

## 四、SoC 判断：倾向 ASTRA，但**未证实**

### 支持"与 ZV-1F 同平台（CXD90045/ASTRA，ARM32）"
1. **crypter 行为与 ZV-1F 完全一致**（都拒绝 CXD90045 密钥）
2. **USB PID 与其重叠 5 个**
3. **它是 ZV-1（2020，BIONZ X / ASTRA）的镜头升级版**，硬件世代接近
4. 627 MB 介于 ZV-1F（443 MB）与 ZV-E10M2（1,091 MB，ARM64）之间

### 反对/未知
- `_k8` 代次在 ARM64 机型上也用 ⇒ 不足以证明 SoC

### ⇒ 结论
**大概率是 ASTRA（CXD90045）系的"新菜单 + 更多功能"版本，但目前证据不足以下定论。**

---

## 五、⇒ 实用性判断：**现在不能当供体**

| 需求 | 状态 |
|---|---|
| 解包固件 | ❌ **密钥未知，打不开** |
| 复用其库（appFw/libObj） | ❌ 取不出来 |
| 复用其资源（.uxc） | ❌ 同上 |
| 作为移植参考 | ⚠️ 只有公开功能列表 |

**⇒ 要把它变成可用供体，必须先拿到 `CXD90045_k8`（或 `CXD90057_k8`）的密钥。**

### 获取密钥的途径（都不容易）
1. 从一台 **ZV-1F 或 ZV-1M2 真机** 里 dump `crypter.elf` / `libcrypto` 的运行状态
2. 从已解包的 ZV-1F 固件里找 —— **但 ZV-1F 的 `/usr` 我们已有**
   （`libupdatertalk.so` 的 `KeyArray` 只是 `SHA256("")`，不是真密钥 ⇒ 需继续深挖 `crypter.elf`）
3. 社区是否已公开 `_k8` 密钥

**⇒ 第 2 条最可行：我们手上有完整的 ZV-1F `/usr`，`crypter.elf`（39 KB）和 `libcrypto` 都在。**

## 六、总结

| 问题 | 答案 |
|---|---|
| ZV-1M2 发布比 ZV-1F 晚吗？ | **是**，2023-05 vs 2022-10 |
| 功能更多吗？ | **是**（Cloud 直传、Wi-Fi 强度、横竖布局等） |
| 是 CXD90045/BIONZ X 吗？ | **很可能是，但未证实**（crypter 代次相同、PID 重叠） |
| 能拿来当供体吗？ | **暂时不能** —— FDAT 解不开 |
| 值得投入吗？ | **值得先花很小力气试**：从 ZV-1F 的 `crypter.elf` 里挖 k8 密钥；挖到就能解 ZV-1M2 |
