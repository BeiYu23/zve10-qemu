# 分区结构对比：ZV-E10 vs ZV-1M2

## 一、★ 结论：**结构完全相同，只有两个分区大小不同**

**16 个分区的【顺序、类型、挂载点完全一致】。**
**差别只有两处：`nflasha1` 和 `nflasha15`。**

```
nflasha1  (Updater)   7.9 MB  →  23.9 MB   （+16 MB）
nflasha15 (usr)     300.0 MB  → 700.0 MB   （+400 MB）
```

**⇒ 因为 nflasha1 变大 16 MB，其后所有分区偏移 +16 MB；
又因 nflasha15 变大 400 MB，其后再多偏 +400 MB（累计 +416 MB）。**

## 四、★ 分区表本身存在哪里

```
0x00000000 - 0x0000FFFF   64 KB 头部区（分区表 + 引导信息）
0x00010000 起             nflasha1 开始
```

**⇒ 分区表在前 64 KB，而我们的镜像只写 `0x2D800000` 起的 300 MB ⇒ 不碰分区表。**

## 五、⇒ 对移植的几个直接含义

**① E10 的 `/usr` **硬上限就是 300 MB**，不能通过换供体扩大**
```
ZV-1M2 的 /usr 是 700 MB，但我们无法在 E10 上重分区
⇒ 300 MB 是硬约束
⇒ 我们的混合镜像 218.3 MiB ⇒ 余 82 MB，够用
```

**② 分区表两版结构相同 ⇒ 刷 E10 的 `/usr` 时不需要改分区表**
```
我们只替换 nflasha15 的内容，分区表保持 E10 原样 ⇒ 正确
```

**③ 存储总量差 416 MB，全部来自 usr（400）和 updater（16）**
```
⇒ ZV-1M2 是同一套固件架构下的"更大存储版本"
⇒ 不是不同的分区设计
```

**④ 这解释了为什么 /usr 用 ext2 而不是更大分区**
```
500 MB 的 /log 用 vfat，300/700 MB 的 /usr 用 ext2
⇒ ext2 用于需要保留权限/符号链接/属主的系统分区
```
