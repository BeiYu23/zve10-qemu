# ZV-1M2 结论（已解出 model ID）

## 一、决定性数据：model ID 解出来了

**方法**：`libupdatertalk.so` 的 `Dec_ScrambleInit` 是 `AES_set_decrypt_key(key=KeyArray, bits=128)`
（`movs r1,#128` ⇒ **AES-128**），`Dec_Scramble` 对每 16 字节做 **AES-128-ECB 原地解密**。
用 `KeyArray[:16]` = `SHA256("")[:16]` = `E3B0C44298FC1C149AFBF4C8996FB924` 解 FDAT 头部即可。

`UDTRFIRM` 头结构（`model` 在 `+0x28`）：

| 机型 | **model ID** | 低 16 位 | 版本 | FDAT 大小 |
|---|---|---|---|---|
| ZV-E10 | `0x01030010` | `0x0010` | 2.03 | 372,454,672 |
| ZV-1F | `0x11020010` | `0x0010` | 2.01 | 443,504,912 |
| **ZV-1M2** | **`0x21020010`** | **`0x0010`** | 2.01 | **627,176,720** |
| ZV-E10M2 | `0x30030002` | **`0x0002`** | 1.02 | ~1,091,000,000 |

**⇒ 三个 ASTRA 机型（ZV-E10 / ZV-1F / ZV-1M2）的 model 低 16 位都是 `0x0010`；
ARM64 的 ARGO 机型是 `0x0002`。**

**⇒ ZV-1M2 与 ZV-1F / ZV-E10 是同一平台族（ASTRA / CXD90045 / ARM32），这是硬证据，不是推测。**

## 二、其他佐证

| 证据 | ZV-1M2 |
|---|---|
| crypter 行为 | 与 ZV-1F 完全一致（都拒绝纯 CXD90045 密钥） |
| USB PID 重叠 | `0x448 0x47D 0xD24 0xD25 0xE06` 与 ZV-1F 相同，另加 `0xE7A` |
| updater PID | `0x03E2`（与另两机型相同） |
| FDAT 大小 | 627 MB，比 ZV-1F 大 **41%** |

## 三、功能对比（公开信息）

| | ZV-1F | ZV-1M2 |
|---|---|---|
| 发布 | 2022-10 | **2023-05（晚 7 个月）** |
| 镜头 | 定焦 20mm | **变焦 18-50mm** |
| 新增 | — | **Cloud 直传、Wi-Fi 强度、横竖拍摄信息布局、固件更新通知** |

## 四、⇒ 结论

**是的：ZV-1M2 就是 CXD90045/ASTRA 系（BIONZ X 平台、ARM32），且比 ZV-1F 发布晚、功能更多。**

## 五、⚠️ 但载荷还解不开

| 部分 | 状态 |
|---|---|
| **头部元数据**（model/version/region/大小） | ✅ **可解**（AES-128-ECB + SHA256("")[:16]） |
| **载荷**（tar、各分区镜像、`appFw.so`、`.uxc`） | ❌ **需要 `_k8` 的 CBC 密钥** |

**验证**：对 `0x24200`（payload 起始）做同样的 ECB 解密，熵仍是 7.58（随机）⇒ 载荷用的是另一套密钥。

**⇒ 所有已知代码里（ma1co fwtool / PMCA-RE / 本仓库研究）都只有 CXD90045 一代实现，
没有 `_k8`。`crypter.elf` 自己不导入 AES（全走 `Dec_Scramble`），所以 k8 密钥不在这两个库里。**
