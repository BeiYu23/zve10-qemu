# ZV-E10 实机操作 —— 硬性安全规矩

> 本文件是**约束**，不是建议。任何与实物机交互的操作都必须先对照本表。

## 🔴 规矩 0（最高优先级，用户 2026-10-25 明确下达）

> **任何时候不得覆盖 `/tmp/jiritsu/libJit.so`，也不得向相机写入新的 `.so`，
> 除非用户明确同意。**

**原因：** 2026-10 曾因向相机送入一个坏的 `dump.so` 导致变砖。
`.so` 是**可执行代码**，且 libJit 通道会在维护进程里 `dlopen` 它 ——
一个坏文件就可能在无恢复机会的位置执行。

**⇒ 现行做法：**
- 相机上**已有并验证可用**的 agent：`/log/agent_v14.so`（18,104 B，已在真机跑通）
- **通过 TCP 7777 的 RUN/PULL/PUSH 通道操作相机**，完全不碰 `.so` 写入
- 需要新载荷时，**先征求用户同意**，并在武装前走 `payload_guard` 预检

## 🔴 规矩 1：不写 `/etc`

```
✗ /etc/ld.so.preload        ← 当初变砖的直接原因
✗ 往 /etc 或 /tmp 写大文件   ← 二者与 /var 共用 12 MB (nflasha10)
```

**`/etc`、`/tmp`、`/var` 是**同一块 12 MB vfat 分区**（`nflasha10`）。
写满后 `/etc` 无法清理 ⇒ **不可恢复**。

## 🔴 规矩 2：不写 `/usr`

**`/usr`（nflasha15）以 `ext2 ro` 挂载 —— 写操作直接失败。
「改 /usr 再重启恢复」这条路**不存在**。**

## 🟡 规矩 3：允许的操作

```
✓ 只读：dd if=/dev/nflashaN、cat /proc/*、读 /log
✓ 写 /log（nflasha11，独立分区，剩余空间充足）
✓ 写 /setting（nflasha2，独立分区）
✓ mount --bind（运行时覆盖，重启即恢复）
✓ TCP 7777 的 RUN / PULL / PUSH
```

## 🟡 规矩 4：改动必须可回滚

| 改动类型 | 回滚方式 |
|---|---|
| `mount --bind` | 重启即恢复（天然）|
| `/log`、`/setting` 里的文件 | 删除即可 |
| **`.so`（禁止，除用户同意）** | **无天然回滚 ⇒ 必须预检 + 看门狗** |

## 🟢 恢复手段（按优先级）

| 情况 | 手段 |
|---|---|
| UI 异常（有 bind）| 等 90 秒 —— agent 看门狗自动 umount + 重启 |
| 想手动回原厂 | 断电重启 |
| 反复失败 | 放 `/log/zv1f_ui/safemode` ⇒ 永久拒绝武装 |
| 完全无响应 | 拔电池 |

## 会话纪律（踩过的坑）

**USB 侧：**
- 服务模式有**空闲超时**，send/read 分开做会在间隙断开
- `--keep`（留在服务模式）会让相机**卡在过渡态，甚至需要拔电池**
- **⇒ 所有 USB 操作必须在一次会话内完成，结尾发 `STOP_SENSER` 干净退出**

**网络侧（推荐）：**
- **`10.42.0.158:7777`，毫秒级，不占用 USB 会话，无需插拔**
- 优先用网络通道做一切可做的事
