# 会话在 5~9 分钟后被强制退出：电源域行为（2026-10-23）

## ★ 更新（2026-10-23）：机制已定位到 Darwin 电源 MCU

同族机型（ILCE-7M4-RE）的 payload 文档写明：AP 之外的 **Darwin 电源 MCU**
在 `0x200026FC` 维护四个看门狗递减计数，"归零即杀整机，BootROM 上下文里
没有任何东西会重置它们"。ZV-E10 固件里同样存在该链路（SIO `0xF1005000`
12 处、字串 "Darwin" 71 处）。

推论：**只要 payload 周期性地与 Darwin 做一次 SIO 交换（读也算喂），
会话就不再受 5~9 分钟限制**——这正是社区"定时发 `oem darwin`"的经验。

详见 [darwin-power-mcu.md](darwin-power-mcu.md)（协议、寄存器差异、
真机三步探测法与落地计划）。下文是定位到此之前的实验记录。

## 现象

BootROM 串口注入 → fastboot payload 正常运行一段时间（实测 **5~9 分钟，有波动**）
后，USB 设备消失。相机随后**自行开机**（电源按钮处于 OFF 也一样）。
社区反馈：C 口机型在串口模式下都会这样，属"空闲自动开机"。

## 已排除（都是实测，不是推测）

| 假说 | 实验 | 结论 |
|---|---|---|
| TIMER-IP 看门狗跨 XRESET_REQ 幸存 | 新 payload 启动即 `wdt_kill()`，实测 `WDT TIMERCTL=0 / TIMERCMP=0 / RSTREQ=0` 全 0，**仍然死** | ❌ 排除（但不是唯一风险，`wdt_kill` 保留） |
| USB 空闲 / 主机 autosuspend | 2 秒一次 `getvar` 心跳**进行中**照样死；设备 `power/control` 实测已是 `on` | ❌ 排除 |
| AP 侧软件复位源 | 内核 `cxd900x0_poweroff()` 是空实现（"not implemented yet"），AP 没有主动断电路径 | ❌ 排除 |

附带证据：**连续工作的会话不会死**（写路径验证、六道门救砖都从头跑到尾），
停下来思考/写脚本的长间隙会话都死了——但心跳实验证明这不是"USB 活动"能救的。

## 结论：死因在 AP 之外的电源定序器

CXD90045 的电源/定序由 AP 之外的一层控制（PMIC / sub-MCU 域）。它在
"调试/串口启动状态"下有一条**墙钟等待**：等不到正常开机进度，就强制复位
并走正常开机流程（相机自己"开机"就是这一步）。因此：

- **payload 里杀任何 AP 侧看门狗都无效**——它不在 AP 里
- 心跳、保持 USB 活跃都无效
- 会话寿命是**固定预算**，不是可以"喂"活的东西

## 对策：把会话当作有预算的批次（工程正解）

不要试图延长会话，而是让所有操作**在预算内完成或可断点续传**。

### 1. 提速（已做）：stage2 v3 多块传输

- CMD18/CMD25 多块，单次 128 块（64 KiB）
- 数据阶段时钟 400 kHz → **~25 MHz**（eMMC 向后兼容模式上限 26 MHz，无需 CMD6）
- 300 MiB 全量传输从"数小时"降到**约 2 分钟量级** → 单会话可完成

### 2. 断点续传（待实现）

`n15_dump.py` / 刷写工具设计成：

- 按 64 KiB 块推进，每块完成后把 `(起始块, 已写字节, sha)` 写进 checkpoint 文件
- 会话死了 → 重新注入 → 从 checkpoint 继续，不重头来
- 每会话时间预算（默认 180 s）用尽就主动退出并保存进度，避免半路被电源域打断

### 3. 重新注入成本可接受

一次注入约 1~2 分钟（含换线），预算 5~9 分钟 ⇒ 单会话有效工作时间 ≥ 3 分钟，
配合多块传输足够完成 300 MiB 的读/写。

## 下次硬件会话的验证顺序

1. 新 payload 注入 → `stage2_selftest.py`（T1/T2/T5/T6 只读；T3/T4 零净变化写）
   —— 多块 + 25 MHz 必须先在预算内跑通
2. 若 T6 吞吐达标（目标 > 2 MiB/s）→ `n15_dump.py` 一次会话 dump 完 300 MiB
3. 否则上断点续传，分 2~3 个会话完成
4. 之后再谈真机刷 hybrid 镜像

## 仍未知（诚实记录）

- 电源定序器这条墙钟的具体数值与触发条件（实测 5~9 分钟，有波动，可能受
  电池电压/USB 供电路径影响）
- 是否存在"正常开机进度"寄存器可以让 payload 冒充（未找到：内核侧无
  PMIC 驱动，电源控制不在 AP 内；ROM 里也未定位到周期性喂狗写）
- 冷启动（`--no-reset`，不打 GP27 脉冲）是否改变这个预算——一次廉价实验，
  下次可顺手做
